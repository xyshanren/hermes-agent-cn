## 三大结构性事实（先说结论的依据）

1. **上游把 CN 主力平台从 core 搬进 plugin**（W-7 / B-1）：weixin / qqbot / yuanbao 从 `gateway/platforms/` 整目录搬到 `plugins/platforms/<name>/adapter.py`，并配套 `PlatformEntry` 元数据链（B-11：env→config 行、allowlist、cron home vars、bot-bypass 闸门、status label 全改由 plugin 声明）。CN 这三个文件**全被 CN 改过**（weixin 独有 ~1,000 行：multiplex 拆分、iLink ret、tokenless 重发、媒体腿、secret scoping、voice、markdown chunker；K-11/K-14/K-17 落点都在里头）。**bump 时不能 cherry-pick，必须逐文件手工 re-port 到 plugin 布局**，且 B-1 与 B-11 必须同批（否则平台静默失真）。
2. **上游 46/48 核心依赖带 `python_version >= '3.14'` marker**（B-2/B-14）：照抄 upstream pyproject → CN py3.11 下 46 个核心依赖全部不被安装。`.python-version`=3.11、`requires-python=">=3.11,<3.14"`。**必须手工剥 marker + 自己 `uv lock`（3.11 目标）**。配套：`a274d3388f`/`b31923c8a7` 修 3.14-only 语法的 forward ref（gateway/platforms/{base,helpers}.py 等 7 文件），**不带这两条 CN py3.11 直接 import 失败**——且这两文件正是 CN 本地改过的，冲突要手工解。
3. **`cli.py` 巨型拆解**（B-4）：上游 cli.py 18,664 → 1,796 行，hermes_cli/ 267 → 754 文件，argv 层搬到 `agent/legacy_cli.py`。CN 的 cli.py 仍是 18,664 行单体，且 CN 本地 CLI 改动（glyph layout、/refine、/heartbeat、voice）落在被搬走的那 18k 行里。**bump 前需二选一**：先接上游拆解，还是整文件保留 CN 版逐条补上游功能。

## CN 特色方向：session 授权粒度（本轮独立实现，不提上游）

**背景**：2026-09-26 事故真因 = session 级 pattern 批准按**描述字符串 key**授权，一次"删两个 lib 目录"的 rm -rf 批准静默放行了 326 目录的 find|xargs rm（详见 docs/approval-classifier-gaps.md）。

**上游对照**（agents 发现）：上游本窗口给了两个相关但**不同 grain** 的新物——
- A2（配置级粒度）：permanent allowlist 删除即刻收回 + pending always-save 不得写回已删条目；
- A4（回合级粒度）：execute_code 整脚本闸门按 `viewer_turn` contextvar 区分 admission origin 豁免。

两者都在"批准覆盖多大范围"方向，但**都不是 CN 事故的 grain**（CN 事故是"同 pattern key 跨命令形态共享"）。上游的 session_key 语义**只在 one-gateway runtime 下成立**——CN 不 bump 则 A2/A4 无 host 可落。

**CN 特色实现方向**（本轮在同步分支上做，独立于上游）：
1. session 批准的 key 从**描述字符串**改为**命令形态指纹**（形状变了重新批准）；
2. 命中路径数量/批量语义（`-exec`/`xargs`/通配）变化时强制重弹；
3. 文档层提示：`[s]ession` 批准的是"这一类命令形态"，不是"这一次操作"。

**与上游关系**：殊途同归但键不同。bump 后上游 session_key 与 CN dm session key（K-17）并存，需在 bump 时明确优先级映射；但 CN 本轮的"命令形态指纹"是独立增量，不受上游影响。
